## Other P7 work

- **Compression:** photos become ≤ 300 KB JPEGs, upright, with **no EXIF** (no GPS, device or time data in the file). Tested with a 3000×2000 image carrying GPS EXIF and orientation 6.
- **Server checks** on `complete`: size, JPEG magic bytes and SHA-256. Wrong ones end `rejected` with the reason and are never stored.
- **Access:** photos are visible only to those who can see their source or test (row-level security). Another district's phone gets `404` and cannot attach photos to the source either.
- **Collect screens:**
  - "Photos of this source" on the source page;
  - "Photo of the tester display (optional)" on the result;
  - thumbnails with waiting / uploaded / refused badges;
  - Settings → "Upload photos on mobile data";
  - the Sync screen counts waiting photos.
- **Background:** the Android worker uploads photos after its sync, following the same Wi-Fi rule.
- **Wipe:** a revocation wipe also deletes photos.
- **Storage:** SeaweedFS requires the S3 key pair from `.env` (anonymous → 403). The API refuses to start in production with the development storage secret.
