### Chaos results (live, 2026-10-10)

```text
#1 a week offline syncs completely, with no duplicates            ✓
#2 a sync cut off mid-way resumes with no loss or duplication     ✓
#3 two phones edit one source offline: the expected conflict      ✓
#4 clocks a year wrong: flagged, not lost                         ✓
#5 a failing server: backoff grows, no busy retry loop            ✓
gate: Collect → Console with the collector, and Console → Collect ✓
gate: 200 pending records … 203 records in 0:00:08.76 (pulled 232) ✓
```

What each scenario does:

- **#1 a week offline:** 7 days × 4 visits (≈ 200 records, some unsafe with alerts), then one sync. Every record is `sent`, none refused. A second phone in the village pulls identical counts.
- **#2 a sync cut off mid-way:** the proxy cuts the response after 64 bytes, so the server applied the batch but the phone never heard back. The 35 records stay pending. The retry answers `duplicate`, and the second phone sees each source once.
- **#3 two phones edit one source:** phone A marks it broken, phone B (still at version 1) marks it partly working and renames it. B gets `conflict` (`kept_server:functional_status`). After its pull, B shows "broken" with its own new name. The conflict is stored for stakeholders.
- **#4 clocks a year wrong:** sessions are stored with `device_time_in_future` or `device_time_too_old` flags. Nothing is refused.
- **#5 a failing server:**
  - connections first hang (3 s client timeout), then get reset;
  - for 2 s after a failure, no further attempts are made;
  - each forced failure waits about twice as long as the last (5 s → 15 min cap);
  - when the server recovers, the records are sent.

## Other P6 work

- **Server:** idempotent per-record push; savepoints with parents first; source-code clashes renamed; alert state machine (invalid transition → conflict, reopen → new linked alert); server classification once readings arrive; clock flags; gzip requests and responses.
- **Pull:** `reference`, `area:<id>` and `scope` streams; commit-order-safe cursor (tested with a slow transaction); tombstones; other phones' collector details withheld.
- **Signing:** the query string and a random nonce are now signed, with a shared Dart/Python vector.
- **Local database v2:**
  - sync state (cursor, backoff, last error) and a run lock;
  - migration test v1 → v2 keeps unsent records.
- **Collect:**
  - sync on start, return, network back, 20 s after new records and every 15 min;
  - Android background worker (WorkManager, network required);
  - Sync screen with "Sync now", last sent, the next try, and refused records with plain reasons;
  - revocation during sync → export-then-wipe.
- **Console:**
  - bearer token refreshed on demand;
  - sync after sign-in or unlock, on return and every 15 min;
  - "Latest tests" card with "Sync now";
  - the web pulls into memory.
